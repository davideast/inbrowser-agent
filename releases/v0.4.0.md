# @inbrowser v0.4.0

This release turns the inbrowser stack into a fuller browser-native runtime for model calls, agent sessions, resumable streams, workspaces, and sandboxed tool execution.

All packages are published together at `0.4.0` so users and agents can install a coherent set without juggling package-specific version numbers.

## New packages

`@inbrowser/workspace` is now part of the stack. It provides browser-native workspace primitives: memory/OPFS filesystems, scoped paths, shell execution, package/import-map support, React preview compilation, git helpers, snapshots, and agent-tool adapters.

`@inbrowser/sandbox` is now part of the stack. It layers orchestration over a workspace with bound tools, events, checkpoints, artifacts, and agent-facing runtime semantics.

## Workspace and sandbox APIs

Workspace adds browser filesystem, shell, package, preview, git, and snapshot primitives.

Sandbox exposes a cohesive instance API:

```ts
const sandbox = await createWorkspaceSandbox({ workspace });

await sandbox.tools.run('write', {
  path: '/work/src/App.tsx',
  content: 'export function App() { return <h1>Hello</h1>; }',
});

const beforeEdit = await sandbox.checkpoints.create('before edit');

await sandbox.tools.run('edit', {
  path: '/work/src/App.tsx',
  oldText: 'Hello',
  newText: 'Hi',
});

await sandbox.checkpoints.restore(beforeEdit.id);
```

Tool execution and checkpoint operations emit sandbox events from the sandbox instance itself.

## Agent runtime

`@inbrowser/agent` now includes reusable context-window and token-usage logic under the usage surface, including next-request context snapshots, session usage aggregation, request timeline rows, compaction helpers, cache/reasoning/cost projections, and turn metric accumulation.

The sandbox bridge works with the cohesive sandbox API, so hosts can adapt installed sandbox tools into agent sessions without passing around loose tool runners.

Agent traces now carry richer usage fields, including reasoning tokens and cost where providers expose them.

## Model layer

`@inbrowser/model` adds normalized usage helpers for prompt/output/cached/reasoning tokens and cost.

Provider usage parsing is improved for OpenRouter and OpenAI-compatible providers, including cached prompt tokens, reasoning tokens, and cost fields where available.

Requesty is now available as an OpenAI-compatible provider.

Thinking splitting and tool-call parsing remain available from the model root for provider and local-engine streams.

## Examples

New script examples make each package easier to try without API keys or browser UI:

- `examples/model-basic`
- `examples/agent-basic`
- `examples/resumable-basic`
- `examples/relay-basic`
- `examples/workspace-basic`
- `examples/sandbox-basic`

Browser examples are also available for workspace and sandbox exploration, while richer product UI work can continue separately.

## Docs and site

Documentation now covers the workspace and sandbox packages, including tutorials, how-to guides, reference pages, and explanations. The site chunking/indexing flow includes the new package docs.

## Notes

`@inbrowser/workspace` and `@inbrowser/sandbox` are first-time npm publishes in this release.

Internal package dependencies should resolve to `^0.4.0` in the published tarballs.
